# xcal 架构设计决策

> 设计备忘录，记录重要的技术决策和理由。新手从 README.md 开始。

---

## 模块拆分原则

以**数据流**划分，非按功能划分：

```
公历日期 → 儒略日 → 天文计算 → 节气 / 农历 / 真太阳时
                      ↑ 核心 + ΔT
```

- `core/` — 天文算法（eph0 + 常数 + ΔT），不依赖其他模块
- `calendar/` — 历法逻辑（农历/节气/干支），依赖 `core/eph0`
- `time/` — 时间工具（儒略日 + 真太阳时）
- `geo/` — 地理坐标

## 农历算法选择：定朔定气 vs 平朔平气

| 方案 | 精度 | 复杂度 |
|------|------|--------|
| 平朔 | 固定 29.53 天周期 | 低（但农历有大小月） |
| 定朔（天文公式） | 实时计算日月黄经 | 高 |

选择定朔是因为：农历需要实时计算日月黄经，查表法无法覆盖全部历史。

## 节气角度映射约定

传统节气序号（0=立春 → 黄经 315°）与西方天文学的 0° 春分不对齐：

```
JIEQI_NAMES[n] → 黄经 = ((n + 21) % 24) * 15°

n=0  立春→315°
n=3  春分→0°
n=9  夏至→90°
n=21 冬至→270°
```

## 儒略日的公历/儒略历分界

1582-10-15 之后用格里高利历公式（加 b = 2 - a + a/4），之前用简单儒略历公式。分界 JD = 2299161。

## 牛顿迭代求根策略

**节气**：固定步长 `err * 365.25 / 360.0`，因为太阳角速度稳定。

**朔日**：数值微分 `delta / deriv`，因为日月相对角速度不稳定（月亮受摄动大）。

## 朔日纪元

使用已知精确朔日 `JD 2451550.257`（2000-01-06 18:14 UTC）作为索引锚点，避免每次从冬至反推的累积误差。

```
moon_jd(n) = 纪元 + n * 29.530588853 → 牛顿迭代精化
```

## 当前精度瓶颈

月亮 627 项模型精度已达 ~0.03°（JPL DE441），但少数月份的新月时刻仍有 ~0.5 天的 UT 日历日边界偏移。原因是：

1. **新月计算误差**（627 项无法完全收敛到 `moon_sun_delta_deg < 1e-8` 的严格约束，约 13 小时差）
2. **边界条件**：当新月发生在 UT 午夜 ±13h 范围内，`to_ymd()` 可能分到不同日历日

### 历表精度上界

| 方案 | 月球黄经精度 | 朔望时刻误差 | 系数表大小 | 纯 Rust |
|------|-------------|-------------|-----------|---------|
| 当前 (ELP/MPP02 × 627) | ~1-2" | ±30s | ~12KB | ✅ |
| JPL DE440 | ~0.01" | ±1s | ~50MB | ❌ |

**DE440 不引入。** 理由：

1. **朔日只落到日期精度**，±30s 已够，DE440 的 ±1s 对农历日用无增益
2. **ΔT（地球自转变化）才是真正瓶颈**——公元前的历史推算误差可达 ±数分钟，DE440 的亚角秒精度对此无帮助
3. **零外部依赖原则**——50MB 历表远大于 xcal 完整源码，且无纯 Rust DE440 解析库

**0.5 天日历日边界问题优先于历表精度。** 这是`floor(jd + 0.5)` 日界归属 + 级数项数收敛的问题，换 DE440 也解决不了——真正修法是从 627 项扩展到 ~1000 项，或加入后处理修正。

## 农历算法：日历日对齐 vs JD 分界

早期版本直接用 `floor(jd - nm_jd) + 1` 算农历日，与"新月 UT 日历日为每月第一天"不一致。修复后改为：

1. 将新月 JD 通过 `to_ymd()` 转为 UT 日历日期（`floor(jd + 0.5)` 定义日界）
2. 用日历日比较定位月份（`moons[i] > target`）
3. `day_in` = `days_between(nm_date, target) + 1`
4. `lunar_to_solar` 逆向：`target_jd = nm_jd + (day - 1)`

## 外部依赖策略

零外部依赖，可选 serde。理由：
- 天文算法纯数学，不依赖系统日历或数据库
- 便于 crates.io 发布
- CI 无网络依赖

## 可发布组件

xcal 不依赖 xstars 的任何代码，可独立发布到 crates.io。
`lib.rs` 的根级重导出供 xstars 直接 `use xcal::*`。

## 主要决策记录

1. 定朔定气替代平朔平气（实时天文计算，非查表）
2. 节气角度以立春=315° 为映射基准（非天文学 0° 春分）
3. 朔日纪元锚定 `JD 2451550.257`（避免冬至反推累积误差）
4. 牛顿迭代：节气用固定步长，朔日用数值微分
5. 农历日历日在 `to_ymd()` 上对齐，而非 JD 差值
6. 日历推断使用 `moons[i] > target` 比较，而非 `floor(jd - nm_jd)`
7. 零外部依赖，可选 serde，可独立发布到 crates.io
